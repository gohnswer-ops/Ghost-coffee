# Ghost Caffee Web v7.4.4

نسخة الويب لتطبيق Ghost Caffee. يستخدم التطبيق Firebase Authentication باسم المستخدم وكلمة المرور (بهويّة داخلية مشتقة من اسم المستخدم) وFirebase Realtime Database فقط. لا Google sign-in ولا Storage أو Cloud Functions أو Firestore.

## التغييرات المنطقية

- الحظر يمنع الإرسال من واجهة المستخدِم ويخفي رسائل المحادثة الخاصة التي تقع ضمن نافذة الحظر، ويحتفظ بتاريخ النافذة بعد فك الحظر. تُحدّث قائمة الحظر والكاش مع محاولة إزالة المتابعة وجهة الاتصال ورفض طلبات المراسلة المعلقة.
- البلاغات مدعومة لأنواع المستخدم والرسالة والقصة. يجري التحقق من الهدف والمرسل/مالك القصة ومعرّف المحادثة والسبب، وتُمنع البلاغات الذاتية والبيانات المزورة. لا يسمح النظام بمراجعة البلاغ دون اتصال، ولا يُغلق البلاغ قبل نجاح إجراء المراجعة.
- طلبات المراسلة تستخدم معرّف الطلب/المحادثة المحدد عند الإلغاء والرفض. إنشاء طلب جديد بعد الرفض يستخدم موضوعًا جديدًا، ويُعاد استخدام موضوع أعيدت الموافقة عليه لتفادي النسخ المكررة.
- المتابعة والفك تحدّث الفهارس المحلية والخادمية في الجهتين وتخزن حالة `false` حتى لا يظهر وضع متابعة قديم في المعاينة غير المتصلة.
- حذف المحادثة يخفيها من قائمة المستخدم الحالي فقط ويحفظ علامة إخفاء محلية؛ لا يحذف رسائل الطرف الآخر. إنشاء محادثة لاحقة يمكن أن يبدأ موضوعًا جديدًا.
- بيانات «حول التطبيق» شخصية: الحساب الحالي والحالة ومعرّف الحساب/الجهاز فقط، ولا تعرض إحصاءات إجمالية عن مستخدمي التطبيق.
- مستمع حالة الحساب يوقف الجلسة المفتوحة إذا تحولت حالة الحساب إلى `banned` أو `deleted`.

## الكاش والعمل دون اتصال

- يستخدم IndexedDB كاشًا مفصولًا حسب UID ويسجل الرسائل المستلمة كعناصر مستقلة. تُدمج الدفعات الجديدة مع المحفوظ سابقًا بدلاً من محو التاريخ القديم.
- تُخزّن بيانات المحادثات والملفات الشخصية والقصص التي جرى تحميلها، وتُستعاد الواجهة من بيانات الجهاز أولًا بعد جلسة ناجحة سابقة، ثم تتم المزامنة في الخلفية عند توفر الاتصال.
- الرسائل التي وصلت إلى الجهاز سابقًا تبقى قابلة للعرض دون اتصال. لا تُرسل عمليات الرسائل الجديدة أو الحظر أو البلاغات أو المتابعة أو الحذف دون اتصال؛ وتُعرض رسالة توضح الحاجة للاتصال.
- Service Worker يخزن ملفات الواجهة الثابتة والخطوط فقط، ولا يخزن استجابات Firebase Auth أو Realtime Database. لا تحفظ كلمات المرور.

## حدود الحظر والقواعد

وفق طلب صاحب المشروع لم يتغير `database.rules.json`. الحظر الحالي مطبق في واجهة العميل وعلى العرض والكاش؛ إذا كانت القواعد الحالية تسمح بالكتابة المباشرة في مسار رسالة، فلا يمكن ضمان منع عميل معدل من تجاوز واجهة الحظر. enforcement قطعي على الخادم يتطلب تعديلًا مصرحًا للقواعد أو طبقة خادم، ولم تتم إضافة Cloud Functions.

## النشر والاختبارات

انشر مجلد الويب على HTTPS؛ لا تختبره باستخدام `file://`. شغّل `bash tests/run_all.sh` من هذا المجلد لإعادة تنفيذ الاختبارات المحلية. نجحت 173 حالة محلية في المجموعات الأربع في هذه البيئة. هذه الاختبارات لا تثبت إعداد Firebase الفعلي أو اتصال الإنتاج.
